# TravelFlow 通用申请管理

轻量通用申请与审批系统。项目采用“通用申请流程 + 预置申请类型配置”，重点展示 SvelteKit 全栈页面开发、服务端角色鉴权、申请状态流转、配置化表单、前后端校验、ECharts 数据可视化和可运行测试。

## 启动

安装依赖：

```sh
npm install
```

启动开发服务：

```sh
npm run dev
```

终端会输出本地访问地址。项目预置四位演示用户，可在左下角入口切换：

- 张三：研发部员工，可发起申请并查看自己的申请；
- 王芳：市场部员工，可发起申请并查看自己的申请；
- 陈敏：客户成功部员工，可发起申请并查看自己的申请；
- 李经理：专职审批人，可审批员工申请并查看统计数据。

生产构建和本地预览：

```sh
npm run build
npm run preview
```

## 目录结构与职责边界

```text
src/
├── lib/
│   ├── client/        # 浏览器端共享能力：当前用户获取、切换用户、角色判断
│   ├── components/    # 可复用 UI 组件：状态徽标、ECharts 图表容器、指标卡片、分页组件
│   ├── server/        # 服务端领域能力：内存仓储、Session、服务端角色鉴权
│   ├── types/         # 领域类型：用户、申请、状态、申请字段
│   ├── config/        # 申请类型配置：差旅、采购、报销、加班的字段和展示规则
│   └── utils/         # 无副作用业务工具：校验、状态机、统计计算、展示适配、图表配置
├── routes/
│   ├── api/           # HTTP API：认证、申请创建/查询/编辑/删除、审批状态更新
│   ├── apply/         # 发起、编辑草稿和驳回申请页面
│   ├── applications/  # 我的申请 / 审批管理列表，以及申请详情
│   ├── statistics/    # 审批人可见的通用申请统计页
│   ├── +layout.svelte # 主布局、菜单与账号切换
│   └── +page.svelte   # 工作台
└── app.*              # SvelteKit 应用入口配置

test/
├── unit/              # 纯逻辑单元测试：校验、状态流转、统计和仓储
└── component/         # Svelte 组件浏览器测试
```

边界约定：

- 页面负责展示和用户交互，不直接保存服务端状态；
- `routes/api` 负责 HTTP 输入输出、身份识别和权限检查；
- `lib/server` 负责数据操作和服务端业务规则；
- `lib/utils` 保持可独立测试，不依赖页面或 HTTP；图表配置也集中在工具层；
- 测试集中放在根目录 `test` 下，按 `unit` 和 `component` 分层；
- 共享类型、客户端工具和 UI 组件统一放在 `lib`，避免路由页面互相复制代码。

## 测试与验收

先安装浏览器测试依赖。首次运行组件测试时执行一次：

```sh
npx playwright install chromium
```

常用命令：

```sh
# TypeScript / Svelte 静态检查
npm run check

# ESLint 代码规范检查
npm run lint

# Prettier 格式检查
npm run format:check

# 业务规则与工具函数单元测试
npm run test:unit -- --run

# Svelte 组件浏览器测试
npm run test:component -- --run

# 一键执行全部测试
npm test

# 单元测试覆盖率报告
npm run test:coverage

# 生产构建
npm run build
```

当前单元测试覆盖率约为 90%（Statements），覆盖通用申请展示适配、申请类型校验、状态流转、角色数据范围、草稿编辑删除、驳回后重新提交和统计计算。组件浏览器测试单独验证状态徽标、分页、指标卡片、图表容器和统计页关键渲染。

当前测试覆盖：

- 申请表单校验、申请类型字段校验、日期范围和金额校验；
- 申请状态流转、草稿排除和部门月度统计；
- 草稿创建、提交审批、审批通过及审批意见记录；
- `StatusBadge` 组件的四种业务状态文案和样式；
- `EChart` 组件的图表容器、尺寸和无障碍标识；
- `Pagination`、`MetricCard` 组件及统计页页面级渲染；
- 申请列表分页、类型/状态筛选和权限范围；
- 通用申请展示适配、金额字段和业务日期归属。

申请列表使用轻量服务端分页，支持页码、每页条数、关键字和状态筛选。接口返回 `data` 与 `pagination` 元信息，默认每页 10 条、单次最多 50 条。统计页通过独立的服务端统计接口获取聚合结果，不受列表分页上限影响；服务端统一执行角色数据范围、时间范围和草稿排除规则。ECharts 仅在图表组件挂载到浏览器后动态加载，普通页面不会同步加载完整图表库。

## 数据统计

统计页面仅对李经理审批人账号开放，使用 ECharts 展示通用申请指标和图表：

- **核心指标**：已提交申请、当前月份申请、审批通过率和金额合计；
- **费用概览**：平均申请金额、最高单笔金额和完成审批量；
- **申请状态分布**：环形图统计审批中、已通过和已驳回申请，不包含草稿；
- **申请类型分布**：环形图比较差旅、采购、报销和加班申请；
- **部门申请量**：横向柱状图比较各部门的已提交申请数量；
- **部门月度申请趋势**：堆叠柱状图展示各部门的月度申请趋势及月度总量；
- **月度金额趋势**：柱状图展示各月份具备金额字段的申请金额。

统计页支持四个固定时间范围：

- **最近一年**：当前月份向前取 12 个自然月；
- **最近半年**：当前月份向前取 6 个自然月；
- **最近三月**：当前月份向前取 3 个自然月；
- **今年**：当年 1 月统计至当前月份。

切换时间范围后，核心指标、费用概览、状态分布、申请类型分布、部门申请单量、部门月度趋势和月度金额趋势都会按所选范围重新计算。月度统计按每种申请类型配置的业务日期归属：差旅按出发日期、采购按期望到货日期、报销按费用发生日期、加班按加班日期；草稿不参与审批人统计。金额统计只纳入差旅、采购和报销等具备金额字段的申请，加班不计入金额。审批通过率按“已通过 ÷（已通过 + 已驳回）”计算，不将审批中的申请纳入分母。当前预置数据使用固定日期和固定 ID，覆盖 `2025-10` 至 `2026-09`，每次启动结果一致。

## 演示业务边界

这是有意简化的两角色演示流程：

```text
张三 / 王芳 / 陈敏（员工）
  └─ 创建、编辑、删除自己的草稿
  └─ 提交自己的草稿进入审批中
             ↓
李经理（专职审批人）
  └─ 查看非草稿申请
  └─ 通过或驳回申请
  └─ 查看申请统计
```

规则说明：

- 员工只可查看自己的申请；
- 员工只能编辑、删除和提交自己的草稿；
- 审批人不提供发起申请入口；
- 审批人不显示草稿，只处理已提交申请；
- 草稿提交后状态从“草稿”变为“审批中”；
- 后端校验权限，前端隐藏按钮只用于改善体验。

## 与企业级系统的差距

为控制轻量演示版复杂度，以下生产级能力尚未实现：

- **持久化与并发**：当前使用内存数据，服务重启后恢复初始数据；未接入 PostgreSQL/MySQL、ORM、事务、乐观锁或迁移脚本。
- **真实认证**：当前是预置用户 + Cookie 演示 Session；未接入账号密码、企业 SSO、OAuth、密码加密、Session 存储和注销。
- **组织与审批链**：审批人固定为李经理；未实现部门树、上级审批、代理审批、多级会签、金额阈值、审批流配置。
- **权限治理**：未实现 RBAC 管理后台、权限数据表、操作审计、数据范围配置。
- **业务扩展**：未实现附件/行程单、预算占用、费用报销、机酒预订、撤回、催办、抄送、消息通知，以及采购/报销的多行明细。
- **列表能力**：当前实现基础服务端分页、搜索和状态筛选；未实现复杂组合筛选、多字段排序、表格列配置和批量操作。
- **工程与运维**：未实现环境变量管理、日志与监控、错误追踪、限流、CSRF、防重复提交、CI/CD、容器化和部署适配器。
- **测试范围**：已有核心逻辑、通用申请展示适配、统计工具、仓储状态流转、申请 form actions 和 HTTP API 权限与异常分支、分页/指标/图表组件和统计页页面级测试；仍未覆盖申请表单、列表筛选、角色切换、图表视觉回归和完整审批链的端到端测试。

## API 概览

- `GET /api/auth`：获取当前演示用户和可切换用户
- `POST /api/auth`：切换演示用户
- `GET /api/applications`：按当前角色获取申请列表
- `POST /api/applications`：员工创建草稿或直接提交申请
- `GET /api/applications/:id`：获取有权限访问的申请详情
- `PUT /api/applications/:id`：员工更新自己的草稿或驳回申请
- `DELETE /api/applications/:id`：员工删除自己的草稿
- `PATCH /api/applications/:id`：员工提交草稿；审批人通过或驳回申请
- `GET /api/statistics?range=year|halfYear|quarter|currentYear`：审批人获取指定时间范围内的统计聚合结果
